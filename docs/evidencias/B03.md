# B03: autenticación y permisos

Fecha: 2026-10-08. Implementado, cierre pendiente de integración y navegador sobre la imagen actualizada.

## Alcance

RF-01/02/03: registro, ingreso, cuenta, administración protegida y salida. Formularios con etiquetas, autocompletado, errores accesibles, escape HTML y CSS adaptable. No se presentan reservas, tickets ni gestión administrativa como ya terminados.

- Registro público asigna USUARIO desde el servidor y omite campos de rol manipulados.
- Correo: trim y minúsculas, validación PHP y unicidad MySQL sin distinguir mayúsculas; admite sufijos con +. Soporte de correo internacionalizado no implementado.
- Nombre: 2–150 caracteres Unicode, sin controles. Contraseña: 8–72 bytes, sin NUL, confirmación obligatoria y PASSWORD_DEFAULT. No se almacenan ni rellenan contraseñas en las vistas.
- Sesión: cookie HttpOnly/SameSite=Lax, modo estricto y solo cookies; almacenamiento privado; renovación del identificador/CSRF al ingresar; vencimiento tras 30 minutos de inactividad; destrucción al salir.
- Cookie Secure en producción y cuando PHP reconoce HTTPS. El despliegue deberá validar HTTPS y configuración del proxy; no se confía automáticamente en cabeceras enviadas por clientes.
- Rol y cuenta activa se consultan en MySQL en cada petición protegida; revocar/desactivar tiene efecto sin confiar en la sesión para conservar privilegios.
- CSRF en todos los POST de autenticación, registro y salida. GET no cierra sesión. Respuestas 403/422/429 para token, validación y límites.
- Límite persistente: 10 intentos por acción/IP remota en 15 minutos, con bloqueo transaccional de la fila. Incluye intentos exitosos y fallidos; usuarios bajo una misma IP comparten el límite. Se guarda HMAC de IP, sin dirección literal. Revisión de retención/limpieza prevista antes de entrega.
- Mensaje de ingreso genérico para cuenta inexistente/inactiva o contraseña incorrecta; verificación de hash ficticio para cuentas inexistentes. No afirmar inmunidad total a diferencias temporales.

## Ejecución Docker reportada y correcciones

El usuario ejecutó verify-linux.sh: migraciones 001/002 aplicadas, 39 unidades correctas en PHP objetivo y conexión MySQL válida. La suite aislada ejecutó MySQL 8.4.11 y llegó hasta la comprobación HTTP de cookie, donde falló; no se registra como suite aprobada.

Causa: la sesión se crea al visitar /admin; /registro reutiliza la cookie y no necesita emitir Set-Cookie otra vez. Se comprueban los atributos en la respuesta inicial sin relajar HttpOnly/SameSite. Además una petición directa observó Apache 500 con cuerpo de CSRF vencido: el código 419 no estándar se reemplazó por 403. Correcciones preparadas, reconstrucción y repetición pendientes.

Modo de desarrollo preparado: override con montajes de código de solo lectura; configuración Compose y Bash correctos. Activación real pendiente. No monta secretos ni reemplaza volúmenes de negocio.
