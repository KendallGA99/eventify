# B04: primera implementación de reservas

Fecha: 2026-10-08. Implementado parcialmente, no cerrado.

## Código preparado

- Catálogo mínimo de eventos publicados futuros, detalle, disponibilidad y umbral de últimos espacios. Los filtros/jQuery/API de B05 aún no están integrados.
- Reserva autenticada por AJAX: CSRF, cantidad entera, precio/total calculados en MySQL DECIMAL, rechazo de duplicado y disponibilidad validada bajo bloqueo de evento.
- Reserva y ticket se guardan en una sola transacción; un fallo revierte ambos. Todas las mutaciones de reserva bloquean primero el evento; la cancelación luego bloquea su reserva.
- Cancelación del propietario con límite estricto >24 horas; repetición idempotente e historial conservado. El servidor usa hora UTC de MySQL, con reloj inyectable solamente desde código para pruebas.
- Historial propio y consulta de ticket por código opaco; propiedad verificada por consulta parametrizada. Ticket no vigente al cancelar reserva/evento o pasar inicio. QR real implementado; verificación HTTP/propiedad en contenedor todavía pendiente, no afirmar RF-14 completo.
- Interfaz adaptable y dos operaciones AJAX. Total visual con BigInt en JavaScript y formato decimal en PHP, sin perder centavos por conversión a flotante.

## QR integrado y comprobación independiente

BaconQrCode 3.1.1 y dasprid/enum 1.0.7, licencias BSD-2-Clause, fijados en composer.lock. Composer 2.10.3 se descargó de getcomposer.org y se verificó SHA-256; Docker repite esa comprobación antes de instalar desde lock, sin plugins/scripts. composer validate correcto con advertencias de licencia de proyecto pendiente y pin exacto deliberado; composer audit --locked --no-dev no encontró avisos conocidos. Esto no certifica ausencia de vulnerabilidades desconocidas.

Se usa el codificador de la biblioteca y un renderizador SVG sencillo de módulos, con zona silenciosa de cuatro módulos por lado. Payload: EVENTIFY:TICKET:<identificador hexadecimal de 64 caracteres>, sin nombre/correo ni URL pública. Ruta /tickets/<código>/qr.svg exige la misma propiedad que el ticket; cabecera privada/no-store. QR conserva el identificador histórico; no representa prueba independiente de vigencia.

Prueba independiente: el método SVG real se ejecutó con PHP temporal 8.3.6 y una instalación temporal de las mismas dependencias compatibles con PHP ^8.1, fuera del proyecto. La plataforma del proyecto permanece ^8.4, sin modificar ni desactivar su comprobación. SVG rasterizado con Pillow y decodificado con libzbar del equipo: identificador exacto recuperado. Artefactos /tmp/eventify-qr.svg y /tmp/eventify-qr.png. No equivale a ejecución en PHP 8.4/Apache.

JavaScript reservations.js comprobado con node --check del runtime incluido. Suite HTTP ampliada para comprobar reserva con precio manipulado, ticket propio, SVG protegido y rechazo de ticket/QR ajeno; ejecución real pendiente.
